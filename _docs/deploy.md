## Architecture

```text
             ┌──────────── one Docker image (Dockerfile, #31) ────────────┐
browser ───▶ │ Next.js standalone server: prerendered static pages + /api │ ───▶ PostgreSQL 16 (#30)
             └────────────────────────────────────────────────────────────┘
local / CI: docker-compose.yml (app + db, #32); Render: render.yaml mirrors it (#34)
AWS: CloudFormation stack → EC2 → Caddy (HTTPS) + app + db (#35)
```

- **Frontend as static + backend, one image.** `next build` with `output: "standalone"`
  prerenders every page to static HTML/JS/CSS (`○ (Static)` in the build output); the same
  Node process serves `/_next/static`, the pages and the `/api/*` backend.
- **SQLite → PostgreSQL.** The TypeORM EntitySchema store now runs on SQLite *and*
  PostgreSQL (`src/server/store/postgres.ts`). Domain code is unchanged. The same
  store/domain/jobs suites run on memory, SQLite and PostgreSQL in CI.
- **Self-contained mode.** Containers set `MAXBALL_DEMO=1`: local accounts, files on the
  `/app/.local` volume and the published demo logins instead of Supabase Auth/Storage
  (the Supabase path stays available for a later real launch, issues #1/#2).

Demo accounts (password `Maxball2026`): `demo1@maxball.example` (user),
`demo4@maxball.example` (teacher), `demo6@maxball.example` (leadership).

## Run locally with Docker Compose

```sh
docker compose up --build -d --wait   # http://localhost:3000
curl localhost:3000/api/health        # {"status":"ok","adapter":"postgres",...}
docker compose down                   # keep data; add -v to delete volumes
```

## Migrate existing SQLite data to PostgreSQL

The app creates the PostgreSQL schema on first start (`store_migrations` v1). Then copy the
SQLite file in one transaction; row counts are verified before COMMIT:

```sh
DATABASE_URL=postgres://maxball:maxball@localhost:5432/maxball \
  npm run migrate:sqlite-to-postgres -- .local/maxball.sqlite --replace
```

Inside the container: `docker compose exec app node scripts/migrate-sqlite-to-postgres.mjs /app/.local/maxball.sqlite --replace`.
Without `--replace` the script refuses to overwrite non-empty tables.

## CI/CD (`.github/workflows/ci.yml`, #33)

`unit` · `browser` · `stack` run on every push and pull request. On `main`, when all pass:
`publish` pushes `ghcr.io/maksatworkspace-sudo/studylist:{latest,<sha>}`, then
`deploy-render` redeploys Render through its hook; the AWS instance pulls the new image
itself and `deploy-aws` waits for it. Both smoke-test `/api/health` until it reports the
new commit SHA. Each deploy job is skipped until its repository variables exist.

**Owner, once:** GitHub → Packages → `studylist` → Package settings → Change visibility →
**Public**, so Render and EC2 can pull the image without registry credentials.

## Render (Docker Compose stack as a Blueprint, #34)

Railway was the first choice, but on 2026-11-03 it refused new projects:
"Trials are temporarily paused for new accounts. Upgrade to a paid plan to start
deploying." Render offers free instances, so the PaaS step runs there instead.

Neither Railway nor Render runs `docker-compose.yml` itself; both map each compose
service to a platform service. [`render.yaml`](../render.yaml) is that mapping:

| `docker-compose.yml` | Render Blueprint |
| --- | --- |
| `app` (the Dockerfile image) | web service, `runtime: image`, `ghcr.io/maksatworkspace-sudo/studylist`, plan `free`, health check `/api/health` |
| `db` (postgres:16) | Render Postgres 16, plan `free`, `DATABASE_URL` from its private connection string |
| `environment` | `envVars` (`APP_SECRET` generated by Render; `APP_URL` falls back to `RENDER_EXTERNAL_URL`) |

Free-plan limits: the service sleeps after 15 minutes without traffic (first request
takes about a minute), the filesystem is ephemeral (uploaded files do not survive a
redeploy), and the free Postgres expires after 30 days.

Owner steps, once:
1. Sign up at render.com with GitHub. Do not add a paid plan.
2. New → Blueprint → select `maksatworkspace-sudo/studylist` → Apply (creates `maxball` + `maxball-db`).
3. `maxball` → Settings → Deploy Hook → copy it. Store it as the GitHub secret
   `RENDER_DEPLOY_HOOK_URL` (`gh secret set RENDER_DEPLOY_HOOK_URL`) and set the variable
   `RENDER_APP_URL` to the `https://….onrender.com` address.

From then on `deploy-render` posts the hook with `imgURL=…:<commit sha>` and waits until
`/api/health` reports that SHA.

## AWS with CloudFormation (#35)

[`deploy/aws/maxball-stack.yaml`](../deploy/aws/maxball-stack.yaml) creates one EC2
instance (security group 80/443 only, IMDSv2, encrypted gp3), an Elastic IP and a monthly
AWS Budget. UserData installs Docker, generates the database password and app secret on
the instance and starts [`docker-compose.prod.yml`](../deploy/aws/docker-compose.prod.yml):
Caddy (automatic Let's Encrypt HTTPS on `<ip>.sslip.io`) → app image → PostgreSQL 16.

Free-plan guardrails: only `t3.micro`/`t3.small`, ≤ 30 GiB gp3, no NAT gateway, no load
balancer, no RDS; the Budget e-mails at 50 % actual / 100 % forecast. Never upgrade the
account to a paid plan. The Elastic IP (public IPv4) is the one billable item, covered by
the free credits.

**Continuous deployment is pull-based.** A push deploy from GitHub would need AWS
credentials, but the free plan denies `iam:CreateOpenIDConnectProvider` through a service
control policy (stack event on 2026-11-03: "explicit deny in a service control policy"),
and long-lived access keys in GitHub are worse practice. Instead
`maxball-autodeploy.timer` runs [`autodeploy.sh`](../deploy/aws/autodeploy.sh) every
minute: when `main`'s head has a published `ghcr.io/…:<sha>` image (CI publishes only
after all tests pass) and it is not running yet, [`deploy.sh`](../deploy/aws/deploy.sh)
fetches that commit's compose/Caddy files, pulls the image and waits for health. The CI
job `deploy-aws` then waits until `AWS_APP_URL/api/health` reports the commit SHA.

Owner steps, once (free-plan accounts are pinned to one region; use that region):
1. CloudFormation → Create stack → With new resources → Upload `deploy/aws/maxball-stack.yaml`.
2. Stack name `maxball`, set `BudgetEmail`, keep the defaults → Submit.
3. When `CREATE_COMPLETE`, set the `AppUrl` output as the GitHub variable `AWS_APP_URL`.

Equivalent CLI:

```sh
aws cloudformation deploy --stack-name maxball \
  --template-file deploy/aws/maxball-stack.yaml \
  --parameter-overrides BudgetEmail=you@example.com
aws cloudformation describe-stacks --stack-name maxball --query 'Stacks[0].Outputs'
```

No SSH port is open. Bootstrap output is in `/var/log/maxball-bootstrap.log` and on the
serial console (EC2 → instance → Monitor and troubleshoot → Get system log). With
`EnableSessionManager=true` (needs IAM role rights) the instance also gets an SSM role.

Remove everything: CloudFormation → `maxball` → Delete, or

```sh
aws cloudformation delete-stack --stack-name maxball
aws cloudformation wait stack-delete-complete --stack-name maxball
```
